# 수급 레이더 (가칭)

**L.L.M Academy의 리서치·기획·산업 분석 수업을 바탕으로, 농식품 수급 정보를 확인하는 웹 서비스를 만들어 가는 개인 프로젝트입니다.**

품목과 산지별 가격·물량 변화, 기상 위험을 공공데이터로 한곳에서 살펴볼 수 있는 서비스를 목표로 합니다. 식품 기업의 사업 구조를 조사하고, 밸류체인에서 문제를 찾은 뒤, 실제 데이터를 확보하고 검증하는 순서로 진행하고 있습니다.

> **개발 진행 중 · 2026-11-06 기준**
> 기업 리서치와 밸류체인 맵, 경매 데이터 수집·정리 스크립트가 있습니다. 현재는 **단계 1: 데이터 검증**을 진행 중입니다. 수급 레이더의 사용자용 웹 화면·자동 수집·예측 모델은 아직 구현하지 않았습니다.

## 어떤 프로젝트인가요?

식품 제조·유통에서는 원료 가격과 공급 물량이 달라지는 이유를 파악해야 합니다. 이 프로젝트는 그중 **원료 수급의 가격·물량·기상 위험**을 살펴보는 데 초점을 두고 있습니다.

- **목표 사용자 가설:** 자체 분석팀이 없는 중소 식품 제조사와 식자재 유통사의 구매 담당자
- **만들려는 것:** 관심 품목의 가격·물량 변화와 관련 근거, 데이터 기준일을 함께 보여 주는 웹 서비스
- **데이터 원칙:** 공공데이터를 기본으로 사용하고, 계산·해석·확인하지 못한 내용을 구분
- **현재 확인 중인 것:** 과거 데이터 확보 범위, 가격 계산 방법, 품목·산지 표준화, 실제 사용자의 필요

사용자와 수요는 아직 가설입니다. 품목 수, 첫 화면의 범위, 예측 제공 여부도 데이터 검증과 사용자 조사 뒤에 정합니다. 가격을 확정적으로 맞히거나 구매·투자를 지시하는 서비스로 설명하지 않습니다.

## 어떤 수업을 바탕으로 하나요?

강의에서 배운 **조사 → 자료 정리 → 자산 선정 → 고객·기획 → 화면 설계 → 산업·밸류체인 분석** 방법을 이 프로젝트에 적용합니다. 강의의 원래 날짜와 개인 프로젝트의 실제 작업 날짜는 구분합니다.

| 강의 | 원래 수업 날짜 | 프로젝트에 적용하는 내용 |
|---|---|---|
| Day 01·02 — 온보딩·Local 오리엔테이션 | 10/26·10/27 | 목표, 저장소, 작업 환경과 리서치 규칙 |
| Day 03·04 — 지역 자산 조사 방법론 | 10/28·10/29 | 공공데이터 명세, 출처 검증, 사용자 문제 조사 |
| Day 05·06 — 콘텐츠 아카이빙·자산 인벤토리 | 10/30·11/02 | 조사 자료 기록, 품목·산지·데이터 후보 비교와 선정 |
| Day 07·08 — 페르소나·디지털 내러티브 | 11/03·11/04 | 대상 고객, 한 장 기획서, 서비스 화면 흐름 |
| Day 09·10 — 산업 구조·밸류체인 맵핑 | 11/05·11/06 | 식품 기업 조사, 돈·데이터 흐름, 병목과 기회 도출 |

원래 수업은 지역 자산과 팀 활동을 포함합니다. 여기서는 이를 개인 농식품 데이터 프로젝트에 맞게 바꾸어 적용하고 있습니다. **강의 기반 학습 프로젝트이며, 모든 수업 과제나 서비스가 완성되었다는 뜻은 아닙니다.**

수업별 산출물과 현재 적용 상태는 [강의와 프로젝트 연결 안내](docs/COURSE_GUIDE.md), 앞으로의 작업 순서와 완료 기준은 [로드맵](ROADMAP.md)에서 확인할 수 있습니다.

기업 조사와 밸류체인은 이 서비스의 문제를 찾기 위한 **같은 프로젝트의 조사 과정**입니다. 기존 과제에는 팀 프로젝트 ‘살피’를 전제로 한 내용도 남아 있습니다. 이를 현재 수급 레이더의 고객·기능으로 확정한 것은 아니며, 살피의 코드·데이터·브랜드·페르소나는 사용하지 않습니다.

기업 조사와 서비스 데이터 조사를 하나의 `research/` 아래에 모았습니다. 모든 명령은 저장소 루트에서 실행합니다.

```text
k-뉴딜/                           프로젝트 루트 (GitHub 저장소: cj_ax)
  README.md                       프로젝트 소개와 읽는 순서
  ROADMAP.md                      단계별 작업과 완료 기준
  DECISIONS.md                    결정 이유와 미결정 사항
  goals.md                        목표 초안
  HANDOFF_GPT.md                  이어서 검토할 때의 상황 정리
  claude.md                       작업·보안·근거 규칙
  .env.example                    값이 비어 있는 환경변수 예시
  docs/
    COURSE_GUIDE.md               강의 내용과 프로젝트의 연결
    DATA_SETUP.md                 데이터 복원·수집·실행 안내
  research/
    company/                     기업 6곳 조사·출처·검증·비교
    bottlenecks.md               기업 공통 병목과 주제 선정 근거
    opendata_catalog.md          공공데이터 후보 목록
    data/                        데이터 명세·정리본 CSV
      archive/                   원본 압축본
      raw/                       수집·복원한 원본 (Git 제외)
  valuechain/                    기업별 밸류체인 맵과 분석
  scripts/                       기업 통합 화면 생성·API 시험·수집·정리
  archive/                       사용자·현장 조사 자료용 폴더
```

## 실행해 보기

Node.js 18 이상이 필요합니다. 저장소 루트에서 원본 압축본을 복원하고 CSV를 다시 만들 수 있습니다. 이 두 작업에는 API 키가 필요하지 않습니다.

```powershell
node scripts/raw_archive.mjs restore
node scripts/build_auction_daily.mjs
```

복원은 같은 이름의 원본 파일을 덮어씁니다. 새 데이터 수집과 API 키 설정은 [데이터 실행 안내](docs/DATA_SETUP.md)를 확인하세요. `.env`는 Git에 포함하지 않습니다.

기업 원페이지나 밸류체인 HTML을 수정한 뒤에는 통합 화면을 다시 만듭니다.

```powershell
node scripts/build_index.mjs
```

## 자료를 읽을 때

- `[F]`는 원문·호출 결과에서 확인한 사실, `[I]`는 해석, `[U]`는 미확인입니다. 기업 자료의 `[n]`은 각 `sources.md`의 출처 번호입니다.
- AI가 제안한 점수·페르소나·기능은 사람의 검증이나 사용자 인터뷰를 대신하지 않습니다.
- 예전 조사 문서에는 당시의 검증 상태가 남아 있습니다. 실제 데이터 현황은 데이터 명세와 정리본 CSV를 함께 확인하세요.
- 데이터의 출처 표시·재배포 조건은 공개 서비스 전에 항목별로 확인합니다. 가격과 위험 정보는 참고용입니다.
